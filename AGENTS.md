# AGENTS.md

## Project
- `sprite-warden` — Python `src/`-layout package (import name `spritewarden`): pixel-art QA gates, SQLite asset catalog, generator routing, a per-provider recipe registry, gate records, Aseprite integration, and an MCP server.
- CLI entrypoint `spritewarden.cli:main`; console scripts `warden`, `spritewarden`, `sprite-warden`. `cli.py` is a thin dispatcher: `hook` / `check-call` go to `enforce/cli.py` before anything heavy is imported; every other subcommand lives in `cli_full.py`.
- Managed with `uv` (hatchling build). Deps: pillow, pydantic, httpx, numpy, rich, mcp (>=2.0).

## Commands
- Install/sync: `uv sync` (a `.venv` already exists).
- Run all tests: `.venv\Scripts\python.exe -m pytest`
- Run one test: `.venv\Scripts\python.exe -m pytest tests/test_judge.py::test_pixel_grid_flat_vs_mixel`
- `uv run pytest` fails on this Windows machine with `uv trampoline failed to canonicalize script path` — invoke the venv python directly instead.
- Stills: `warden judge-still <png> --palette luap-40 [--symmetry] [--vision]`; anchor readiness: `warden judge-still <png> --start-image [--target-height 40 | --size-tier 48-64] [--margin 3] [--facing south] [--char-id ID]`; against an approved anchor: `warden judge-still <view.png> --reference south.png [--facing north_east]` (needs `OPENROUTER_API_KEY`; offline the `vision_reference` gate FAILS).
- Direction sets: `warden judge-views <dir-or-strip> [--cell 64] [--anchor south.png] [--char-id ID]` (a folder of `<facing>.png` / `<prefix>_<facing>.png` files, or a strip in game order down, down_right, right, up_right, up, up_left, left, down_left).
- Direction sets by vision (paid, opt-in): `warden judge-views <dir> --anchor south.png --vision [--anchor-facing south]` compares EVERY view with the anchor and writes `vision_reference` into each view's record; `judge-still --reference south.png --facing north [--anchor-facing south]` for one view.
- Animations: `warden judge-anim <sheet.png> --cell 64 [--walk] [--locomotion legs|wheels|treads] [--char-id ID] [--source STILL.png]` (`--source` = the still it was made from, for `frame_integrity`; locomotion/palette default to the identity's).
- Gatekeeper: `warden review-check <paths...> --require start_image|views|anim|still` (exit 1 + list of files without a current passed `<image>.gate.json`). All judge commands write that record unless `--no-record`.
- Enforcement: `warden check-call --tool NAME --input-file call.json [--project DIR] [--json]` (exit 0 allow/ignore, 2 deny); `warden hook --claude [--project DIR]` (Claude Code PreToolUse: event JSON on stdin, hook response on stdout, always exit 0).
- **One command per stage** (prefer these over the judge commands): `warden stage anchor <south.png>` (pad to the pipeline's canvas, palette snap, `start_image`, game-scale view), `warden stage views <folder> [--anchor A] [--no-vision]` (canvas + palette, the set moved onto the anchor's ground row, `direction_set` AND `vision_reference` for every view against the anchor and the pipeline's declared faces, contact sheet in `_stage/`), `warden stage anim <sheet> --source <still> [--walk] [--cell N]`. Each stops at the first failed gate (exit 1), writes the gate records, logs failures. Untouched provider output is kept in `_raw/` beside the file before any in-place change.
- Route record: `warden pipeline init|set|show|check <character folder> [key=value | faces.back=... | identity.pixellab.id=...]` (`pipeline.json`: anchor, faces, rotation_provider, animation_provider, identity, canvas, palette, locomotion, size_tier, views_dir). `warden rules [--project DIR] [--no-status]` prints the standing rules, the stages, each provider's own character-identity method, where every character is and the repeated rejections (for a SessionStart hook).
- Gallery: `warden serve [--host 127.0.0.1] [--port 8737] [--project DIR] [--no-sync] [--open] [--quiet]` starts the local stdlib asset gallery (browse assets/gates/provenance, pipelines, identities, projects, rejections, providers; `/api/*` JSON, `/img/<id>`, `/thumb/<id>?size=N`); it syncs the project first unless `--no-sync`. The UI can create gallery projects and edit asset tags/project/identity/category in SQLite only (image bytes and gate sidecars unchanged); mutations require loopback, same-origin, and the server's CSRF token. `warden sync [paths...] [--project DIR] [--game G] [--char-id ID] [--category C] [--no-recursive] [--json]` indexes every local PNG (id `local-<sha12>`) with its gate record and nearest `pipeline.json`, preserving gallery-edited organization fields. `warden fetch <provider> [asset_id] [--all] [--max-items N] [--page-limit 100] [--kind character|object] [--cell N] [--palette P] [--out DIR] [--game G] [--char-id ID] [--no-register] [--json]` downloads existing provider work into the catalog: by id (PixelLab bundle, SpriteCook asset, Sprite Fusion asset) or, with `--all`, the whole account library (Sprite Fusion `GET /v1/assets`, cursor-paginated; `--palette` unset preserves the provider's bytes). Imports register as `import-<provider>-<sha12>` with provenance kind `import` (provider asset id, prompt, dimensions, urls); `warden sync` skips files already catalogued by generation/import/sheet (no duplicate `local-` row).
- Rejections: failed judge/stage runs append to the project's `rejections` log (spritewarden.json, default `art_source/rejections.jsonl`) on their own; `warden reject <files> --reason "..." [--by NAME]` records a person's "no" (the image's gate record is marked `rejected`: `passed_gates` returns nothing for those bytes, so it can no longer be a source or go on a review page); `warden rejections [--provider P] [--json]` lists repeat offenders first.
- Identities: `warden identity set <id> --desc ... [--name --game --palette --perspective --width --height --ground-row-offset --prohibit T --feature name:side:#hex[:x,y,w,h] --still facing=path --style-anchor provider=value --locomotion --body-class --size-tier]`, `warden identity show <id>`, `warden identity list`.
- Recipes: `warden recipes` (table), `warden recipes spritefusion direction-set`, `warden recipes rd rotate --json`; tips: `warden recipes [provider] --export-tips OUT.json` (dry run), `--publish-tips`, `--mark-tips-exported`; `warden learn export-tips [--recipes] [--publish | --dry-run]`.
- Generate: `warden generate "<desc>" --type icon --provider spritecook --out <dir> [--input IMAGE] [--force-ungated] [--no-register] [--project DIR]`; `warden sheet <files|dir> --out <sheet.png> --register --game <slug> [--char-id ID]`.
- Others: `warden route "<desc>" --type vehicle`, `warden pad <files|dir> --size 64 [--align bottom-center]`, `warden sheet <files|dir> --out <sheet.png> --palette luap-40 [--engine auto|rust|python]`, `warden pixelize <img> --palette <lospec-slug> [--refine --vision]`, `warden learn seed && warden learn check && warden learn doctor`, `warden learn reflect`, `warden mcp` (`SPRITEWARDEN_NO_LEARN=1` skips the learning scheduler).

## Environment / API keys
- All LLM paths fall back to deterministic local heuristics when unauthenticated, so tests and the QA gates need no keys — EXCEPT the reference comparison (`--reference` / `reference_path`), which reports `unavailable` and fails its gate on purpose.
- `OPENROUTER_API_KEY` — Jev routing, Fusion deliberation, vision judging, OpenRouter image gen. On Windows, `_get_openrouter_key()` (router/jev.py) also reads it from the registry `HKCU\Environment` when the env var is empty. `SPRITEWARDEN_OFFLINE=1` forces `VisionJudge` offline (tests use `VisionJudge(offline=True)` so they never spend).
- `SPRITE_FUSION_API_KEY`, `PIXELLAB_API_KEY` — provider drivers. `ASEPRITE` — path override for Aseprite.exe (else Windows install dirs are auto-discovered).
- `SPRITE_COOK_API_KEY` — SpriteCook driver (alias `SPRITECOOK_API_KEY`; base URL override `SPRITE_COOK_API_URL`/`SPRITECOOK_API_URL`). Read from env, with a Windows `HKCU\Environment` registry fallback like the OpenRouter key.
- `SPRITEWARDEN_PIXEL_SNAPPER` — path override for the Rust `spritefusion-pixel-snapper` binary used by `warden sheet` (else PATH, then `~/.cargo/bin`).
- `SPRITEWARDEN_NO_LEARN=1` — the MCP server does not start the LearningScheduler (no HTTP GETs / LLM budget at startup).
- `SPRITEWARDEN_DB` — path override for the asset catalog database (tests use it; default `<repo>/data/spritewarden.db`).
- `SPRITEWARDEN_TIPSHARE_CMD` — the tipshare MCP stdio server as a JSON array, e.g. `["node","C:/path/to/tipshare/dist/server.js"]`; needed for `--publish-tips` / `learn export-tips --publish` (the child runs with `TIPSHARE_AGENT_ID=sprite-warden`). Unset = dry runs are unchecked and publishing refuses.

## Architecture
- `src/spritewarden/judge/` — deterministic QA gates: `pixel.py` (pixel_grid; scale inferred: >=640x360 = screenshot multiple, else `detect_block_size` finds 2..16px fake grids, falling back to `sheet/snap.py`'s edge-profile detector), `palette.py` (palette_adherence, `PALETTE_DISPLAY_NAMES`), `bounds.py` (clipping, symmetry), `start_image.py` (`check_start_image`: square canvas, transparent margin, symmetry >=95% for south/north, drawn height vs `SIZE_TIERS`/target/identity cell, stray components via `animation._connected_pieces`, native pixels, palette, identity marker landmarks), `views.py` (`check_direction_set`: ground row +-1, height +-2px, area +-20%, equal component count with extra parts named, tool side per facing from sided identity features (`LEFT_SIDE_SCREEN_SIGN`), palette; `load_direction_frames` / `direction_frame_files`), `animation.py` (`animation_anomalies`: ground spikes; a DETACHED speck that repeats in >1 frame or exceeds 24px is an error), `integrity.py` (`check_frame_integrity` -> gate `frame_integrity`: enclosed transparent holes above `max(12px, 1.5% of opaque area)` over the source still / the median of the other frames, or opaque area >15% below the still; `enclosed_holes`), `walk.py` (`locomotion` legs|wheels|treads; the wheel box is the connected mass holding the ground-contact pixels, `metrics.base_mass`), `loop.py`, `vision.py` (`VisionJudge`: smell test; `compare_to_reference(facing=, anchor_facing=)` -> `reference_prompt` -> `parse_reference_response` -> `ReferenceComparison` (`invented_parts`, `missing_visible_parts`, `changed_parts`, `expected_hidden_parts`, `tool_sides`, `anchor_elevation`, `candidate_elevation`, `failures()`) -> `reference_gate`; `OrchestratedVerdict` hard-fails on anomalies / perspective mismatch when the model looked), `views.py` also has `compare_views_to_anchor` / `vision_summary_gate` (`judge-views --vision`). Entry fns: `evaluate_still(start_image=, identity=)`, `evaluate_animation(locomotion=, source=)`.
- `src/spritewarden/enforce/` — the gatekeeper (ported from the game repo's `tools/generator_hook.py`). `core.py`: `check_call(tool_name, tool_input, project_root) -> Verdict{decision allow|deny|ignore, provider, operation, reasons, context}`; classification (`mcp__pixellab__*`, `mcp__plugin_spritecook_spritecook__*` / `mcp__spritecook__*`, Bash/PowerShell commands running a `cli_tools` script or `warden generate`, `Artifact` review pages), `RULE_KINDS` (`max_items`, `forbid_args`, `enum`, `multiple_of`, `forbid_inline_image_args`, `forbidden_words`, `no_dimensions_in_prompt`, `loop_engine`, `require_arg_value`, `matte_collision`), source resolution (`path` | `manifest_asset` | `url` | `pixellab_character`), `gate_reasons` (accepts the recipe's `required_gates_before` + umbrellas), `pipeline_reasons` (nearest `pipeline.json`), override file, `recipe_gate_reasons` (for `dispatch`). It reads `data/recipes.json` as raw JSON (`load_raw_registry`): tool mapping and rules are the `enforce` blocks at provider level (`mcp_prefixes`, `read_only`, `spends`, `operation_overrides`, `cli`, `rules`, `source`) and operation level (`stage`, `source`, `rules`). `config.py`: `spritewarden.json` (`manifest`, `override`, `cli_tools`, `review_specs`), `find_project_root`. `images.py`: `matte_fraction` (PIL, imported only when a rule looks at pixels). `cli.py`: `check-call`, `hook`.
- `src/spritewarden/gates/` — `records.py`: `<image>.gate.json` sidecars (`write_record`, `load_record`, `passed_gates`, `is_gated` re-hashes sha256; `require_passed` = the review gatekeeper). Shape shared with the game repo's `tools/generator_hook.py`: `{"gates": {"<name>": {"passed": ...}}, "sha256", "time", "spritewarden", "params"}`; umbrella names `still`, `start_image`, `views`, `anim`.
- `src/spritewarden/repo/` — `AssetCatalog` (SQLite + FTS5 with insert/update/delete triggers; `get_asset`, `delete_asset`), `CharacterIdentity` (`features` with `side`/`marker_hex`/`relative_box`, `turnaround_stills`, `ground_row_offset`, `style_anchors`, `locomotion`, `body_class`, `size_tier`; `build_identity` creates or merges, `parse_feature`) / `SceneIdentity` models, palette registry, `provenance.py` (`register_generation`, `register_sheet`). DB auto-created at `<repo>/data/spritewarden.db` (`SPRITEWARDEN_DB` overrides).
- `src/spritewarden/reducer/` — image reducer (`pixelize`: downscale → k-means pre-quantize → dither → vectorized Oklab snap) + `refine` AI tuning loop (contact-sheet vision scoring, critique→param mapping, convergence). Palettes: builtin names, lospec slugs (`na16` / `lospec:<slug>`, cached in `~/.spritewarden/palettes`), JSON/.tres/.hex files.
- `src/spritewarden/learning/` — self-learning KB (`warden learn`): `db.py` (append-only `learning.db`), `models.py`, `taxonomy.py` (canonical perspective/style normalization), `registry.py` (seeded provider doc/tool sources), `acquisition.py` (conditional-GET fetch + snapshot; MCP `tools/list` probe), `mcp_probe.py` (minimal MCP stdio client: `probe_stdio` for `tools/list`, `StdioSession` for `tools/call`; also used by `tests/test_mcp_server.py`), `recipe_tips.py` (`build_recipe_tips`: one tipshare payload per provider from the registry; `publish_tips`: search first, skip existing titles, record in `tip_exports`; dry run by default), `diffing.py` (deterministic diff + significance), `episodes.py` (record attempts), `curation.py` (cluster → strategy + proposal; doc-event → proposal), `summarize.py` (optional capped LLM, deterministic fallback), `proposals.py` (review/apply gate), `scheduler.py` (background watcher), `doctor.py`, `tipshare_bridge.py`, `project_watch.py`, `cli.py`. `PipelineRouter` appends `[learned]` rules from **active** strategies for the matching scope.
- `src/spritewarden/router/` — `PipelineRouter.route_request`: catalog dedup → Jev (`typesafe/jev-1.13`) or OpenRouter Fusion. `recipes.py` + `data/recipes.json` = the per-provider recipe registry (one entry per provider/operation: `start_image` requirements, `prompt_rules`, `forbidden_words`, `arg_limits`, `required_gates_before/after`, `asset_id_params`, `sources`; provider and operation aliases resolve, e.g. `sf`/`direction_set`, `rd`/`rd_advanced_animation__rotate`). `playbook.py` reads it: `sanitize_prompt_for_provider(prompt, provider, operation=None)` strips the registry's patterns (+ dimensions/counts where the provider says so); `determine_fallback_recipe` fills `rules`, `suggested_gates` and `required_gates_before` from the entry. A `GenerationRecipe` carries provider-specific args via `recipe.params`.
- `src/spritewarden/generator/` — `BaseGeneratorDriver` + PixelLab / Sprite Fusion / OpenRouter / **SpriteCook** drivers, plus `registry.py` (`DRIVER_CLASSES`, `get_driver`, `dispatch`, `ungated_reasons`) so recipes are executable via `warden generate`. `dispatch` refuses a rotation/animation recipe whose input image is un-gated or belongs to another provider's set (`force_ungated=True` overrides and records why) and registers successful outputs in the catalog (`register=False` to skip). SpriteCook uses sync `/v1/api/generate-sync` + `/v1/api/animate-sync` (async job fallback), enforces the recipe palette via the API `colors` hex list, then re-snaps Oklab locally; asset IDs are canonical for reference/edit/animation. `BaseGeneratorDriver.fetch_asset`/`fetch_all` (default unsupported) back `warden fetch`: PixelLab downloads a bundle by `character_id`, SpriteCook `GET /v1/api/assets/<id>`, Sprite Fusion the cursor-paginated `GET /assets` library (or `GET /assets/<id>`) — imports register with provenance kind `import`.
- `src/spritewarden/gallery/` — the local asset viewer (`warden serve`). `server.py`: stdlib `ThreadingHTTPServer` (no framework), routes `/`, `/static/<file>`, `/api/health|summary|facets|assets[?q=&game=&character_id=&category=&asset_type=&perspective=&provider=&limit=&offset=]|assets/<id>|sequence|identities|projects|pipelines|rejections|providers`, `/img/<id>`, `/thumb/<id>?size=N` (PIL lazy-imported, cached); serves only catalogued assets by id. POST `/api/projects` creates project groupings; PATCH `/api/assets/<id>` edits tags/project/identity/category, guarded by loopback + same-origin + CSRF. `data.py`: gallery facade (catalog rows enriched with the `<image>.gate.json`, pipeline status, identities, projects, rejections, provider registry, inferred animation frame layout; `/api/sequence` returns a lightweight queue for filtered results). `sync.py`: `sync_paths` walks PNGs (skips VCS/build dirs), hashes to `local-<sha12>`, upserts with gate record + nearest `pipeline.json` (idempotent), preserving organization fields edited in the UI. Static UI in `gallery/static/` (index.html/style.css/app.js, vanilla JS). `warden fetch` delegates to `BaseGeneratorDriver.fetch_asset`/`fetch_all` (PixelLab bundle, SpriteCook asset, Sprite Fusion library; default unsupported).
- `src/spritewarden/sheet/` — `warden sheet`: `snap.py` (Rust `spritefusion-pixel-snapper` wrapper + pure-Python grid-detect/majority-resample + Oklab palette snap fallback; `find_pixel_snapper`, `snap_image`, `detect_pixel_size`) and `builder.py` (`discover_inputs`, `build_sheet`/`build_sheets`: alpha-crop → uniform cell → align → grid compose + JSON manifest). `pad.py` — `pad_files`/`pad_image`: place provider output (varying canvas sizes, edge-hugging art) on a uniform aligned canvas (`--size`/`--canvas WxH`, per-frame `--grow N`, align/margin, `--fit clip|shrink`, optional palette snap, `--in-place`). MCP tools: `build_sprite_sheet`, `pad_sprite`.
- `src/spritewarden/server/` — MCP server (`warden mcp`). Startup is lazy: `AssetCatalog`/`PipelineRouter` are built on first use (`get_catalog()`, `get_router()`), heavy modules import inside the tools, the learning scheduler is optional. Tools: `search_art`, `get_character_identity`, `register_character_identity` (features, turnaround_stills, ground_row_offset, style_anchors, locomotion, body_class, size_tier; merges into an existing id), `route_generation`, `get_recipe`, `judge_still` (start_image, reference_path, write_gate_record), `judge_direction_set` (vision), `judge_animation` (locomotion, character_id, source_path), `review_check`, `build_sprite_sheet`, `pad_sprite`, `open_in_aseprite`, `pixelize_image`, `learn_status`, `list_learned_proposals`, `approve_learned_proposal`, `record_learning_episode`. Resources: `spritewarden://recipes|playbook|proposals|providers|learn-status`. `src/spritewarden/tools/` — Aseprite integration (Windows-only).
- `scripts/ingest_game_assets.py` — one-off seeder for the `i-require-maintenance` game.

## Gotchas
- Repo was renamed from `slaygent`. Stale `__pycache__` can make tracebacks show `slaygent\...` paths; the `.venv` editable install (`_editable_impl_sprite_warden.pth`) points at this repo's `src`.
- `test_find_aseprite` requires Aseprite to be installed on this host. All other tests run offline; `tests/test_mcp_server.py` spawns `python -m spritewarden.cli mcp` with `SPRITEWARDEN_NO_LEARN=1`.
- Built-in palettes are hardcoded in `judge/palette.py`; `luap-40` is the default reference palette (also `luap-40-plus`, `sweetie-16`). `write_gpl_palette` writes the display name (`Luap-40`) on the `Name:` line and lowercase ids in swatch names.
- `load_palette` treats any bare lowercase slug string (no path separators/extension, not a builtin) as a lospec palette-list slug and fetches it; unknown slugs raise FileNotFoundError only after the fetch fails. Override the cache with `SPRITEWARDEN_PALETTE_CACHE`.
- `pixel_grid` scale inference: `detect_block_size` only counts fully opaque blocks and demands that the half-step offset breaks them, so a flat silhouette is not a grid; a bilinear (blurred) upscale under 640x360 is still invisible to it (reported as native). `scale_source` in the gate metrics says which path decided (`given`, `screenshot`, `detected`, `estimated`, `native`).
- `check_start_image` symmetry runs only for south/north facings (`SYMMETRIC_FACINGS`); `size_tier` must be one of `SIZE_TIERS` (`16-32`, `48-64`, `96`, `128`), or pass `target_height` (+-10%). Strays are 8-connected components under 6% of the main mass; larger detached parts are warnings.
- `check_direction_set` tool-side check needs identity features whose name/description says `left` or `right` AND a `marker_hex`; E/W are skipped (sides overlap in x). Frames must share one canvas size.
- Gate records are written even when gates fail (verdicts are per gate); `passed_gates`/`is_gated` return nothing when the image's sha256 changed. `review-check --require` accepts several names (comma-separated), any one satisfies.
- `walk_mechanics` with `locomotion=wheels|treads` treats the lowest contact row as ground (range must be <=1px); a band that never changes only warns ("does not visibly turn"). The hub box is the connected mass with the most ground-contact pixels inside the bottom `band` rows; other masses there (a held tool) are ignored and reported as a warning.
- The recipe registry is JSON (no pyyaml); `router/recipes.registry()` is lru-cached; `load_registry(path)` loads another file. Operation names kept for compatibility: fallback recipes still use `animate_character_v3` (alias of `animate_skeleton`) and spritecook `generate` (alias of `generate_game_art`).
- Learning DB lives at `<repo>/data/learning.db`; override with `SPRITEWARDEN_LEARNING_DB`. Background-check cadence/caps: `SPRITEWARDEN_LEARN_INTERVAL`, `SPRITEWARDEN_LEARN_MONTHLY_USD`. The first check of a source only establishes a **baseline snapshot** (no event); `doc_events` fire only on real transitions.
- MCP `tools/list` drift probing needs a probe command per provider, e.g. `SPRITEWARDEN_MCP_PROBES='{"pixellab":["python","-m","pixellab_mcp"]}'`; without it `mcp_tools` sources are skipped silently.
- Lospec has no stable machine-readable index (its palette-list HTML is per-request dynamic), so it is **not** a watched source; palettes are fetched directly via `load_palette`/`pixelize --palette`.
- `warden sheet` resolves the Rust snapper via `SPRITEWARDEN_PIXEL_SNAPPER` → PATH → `~/.cargo/bin` (install: `cargo install spritefusion-pixel-snapper`). Rust palette recolor is straight RGB, so the builder re-snaps with Oklab afterwards; when the binary is missing/errors it silently uses the Python grid-detect + majority-resample fallback.

- Enforcement must stay import-light: `spritewarden.cli`, `spritewarden.enforce` and `gates/records.py` import no numpy / PIL / httpx / pydantic / rich / mcp at module level (`tests/test_enforce.py::test_enforce_imports_nothing_heavy`). `cli.py`'s module `__getattr__` forwards to `cli_full` but must keep raising for dunder names: the import system probes `__path__`, and answering it once loaded the whole CLI (hook 80 ms -> 400 ms). Never import `router.recipes` (pydantic) or `judge` (PIL, httpx) from `enforce/core.py`; `FACING_STEMS` there duplicates `judge.views.FACING_ALIASES` and a test keeps them equal.
- `check_call` never raises and FAILS CLOSED: an internal error on a spending call is `deny` with reason `gatekeeper error: <type>: <msg>` (a malformed `spritewarden.json`, an unknown rule kind, an unreadable source image); the override file still lets a call through on purpose; an ignored call stays `ignore`.
- A shell command line is checked link by link: `_classify_command` returns EVERY generator call in a chain (a read-only first call no longer hides a spending one); reasons are prefixed `[provider / operation]` when there are several.
- Gate acceptance is exact (`accepted_gates(required, stage)`): a rotation needs `start_image`; `still`, `anim` or `views` do NOT stand in for it. An animation additionally accepts a gated view (`views` / `direction_set`). Only a call whose recipe lists no gate accepts any umbrella.
- `pipeline_reasons`: always enforced when recorded = the stage's provider, the ONE anchor (a rotation whose source file is not `pipeline.anchor` is denied) and, for providers whose registry `identity.entity` is true (pixellab, spritecook), the recorded character id (`identity.<provider>.id` + `also`) on animation calls. With `require_pipeline: true` in spritewarden.json the record is mandatory: no pipeline.json / no stage provider / no anchor / undescribed `faces.back|left|right` / missing entity id each deny.
- Each provider's own character-identity method is data: `providers.<name>.identity` in recipes.json (`entity`, `concept`, `create_with`, `id_args`, `reuse`, `dont`); shown by `warden recipes <provider>`, `warden rules` and in the hook's allow context. Top-level `pipeline_rules` and `stages` are the standing rules `warden rules` prints.
- Review completeness (`gates.records.review_problem`, used by `review-check` unless `--loose` and by the Artifact review gate): a record written by `judge-views` needs a passed `vision_reference` (except the view that IS the anchor), one written by `judge-anim` needs `--source`. Records without `params.command` are not second-guessed.
- `vision_reference`: `faces` (pipeline.json) goes into the prompt as the whole design of the unseen faces; `judge-views --vision` loads it from the nearest pipeline.json. A bare `same_character: false` with no invented/missing/changed part named is a warning, not a failure (the model said it of a view identical to its anchor).
- `judge-still` passes only when the scorecard AND the vision verdict pass (a friendly vision verdict used to outvote a failed reference gate).
- `--force-ungated` on `warden generate` is denied by the hook without the override file.
- Which calls are gated is decided by the `enforce` block, not by `required_gates_before` alone: an operation needs a `source` spec (hook) / a `stage` (dispatch). Stills and edits are never gated (edits create anchors) even where the registry lists `start_image` before them. A PixelLab `reference_image_url` / `custom_start_frame_url` / `end_frame_url` that the manifest cannot resolve is a deny on EVERY PixelLab tool, including style references.
- Hook classification of shell commands is textual: the first token ending in a `cli_tools` script path, the next bare word as the operation, `--flag value` pairs as arguments (dashes become underscores; `--size=64` works). A generator CLI wrapped in another script is invisible to it.
- `matte_collision` reads the manifest file of the source asset; an asset that is not registered is denied by the gate rule first, so the collision test never runs on it. Threshold: more than 2% of opaque pixels within RGB distance 24 (Euclidean).
- `frame_integrity` without a source still compares frames with each other only: a hole in EVERY frame passes (the gate warns). Pass `--source`. Motion that encloses a gap (an arm closing against the body) counts as a hole once it exceeds the threshold.
- `animation_anomalies` speck errors only fire for islands DETACHED from the frame's largest opaque mass; a flicker on the body itself, or a blinking light attached to it, is not caught. A deliberate detached one-frame effect over 24px (muzzle flash, spark) fails: raise `max_speck_size` when calling `check_animation_anomalies` directly.
- `check_direction_set` with an anchor on another canvas than the views skips the absolute ground-row comparison (check `anchor_canvas`, `metrics.anchor_canvas_differs`); it still compares the anchor's content height and area, so a rescaled anchor fails those.
- Reference vision: the model's own verdict is ignored; `parse_reference_response` decides. A "missing" part whose text explains itself by the turn ("turned away", "hidden", "occluded", ...) is moved to `expected_hidden_parts` by a regex (`_OCCLUSION_RE`), so a model that mislabels still cannot fail a view for occlusion. `judge-views --vision` costs one model call per view and, when the south view is the anchor, does not compare it with itself.
- `AssetCatalog` on a database created before the update/delete triggers rebuilds the FTS index once on open (stale rows would otherwise corrupt it on the first update). Generated assets get the id `gen-<provider>-<sha12 of the file>`; sheets `sheet-<game>-<stem>`.
- Recipe tips have their own titles ("<Provider> generator recipes: ... (sprite-warden registry v1)"): the five tips published by hand on 2026-10-07 (tipshare #53-#57) have different titles, so `--publish-tips` would NOT recognise them as existing. Run `warden recipes --mark-tips-exported` first if those are meant to stand in for the generated ones.
