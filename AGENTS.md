# AGENTS.md

## Project
- `sprite-warden` — Python `src/`-layout package (import name `spritewarden`): pixel-art QA gates, SQLite asset catalog, generator routing, a per-provider recipe registry, gate records, Aseprite integration, and an MCP server.
- CLI entrypoint `spritewarden.cli:main`; console scripts `warden`, `spritewarden`, `sprite-warden`.
- Managed with `uv` (hatchling build). Deps: pillow, pydantic, httpx, numpy, rich, mcp (>=2.0).

## Commands
- Install/sync: `uv sync` (a `.venv` already exists).
- Run all tests: `.venv\Scripts\python.exe -m pytest`
- Run one test: `.venv\Scripts\python.exe -m pytest tests/test_judge.py::test_pixel_grid_flat_vs_mixel`
- `uv run pytest` fails on this Windows machine with `uv trampoline failed to canonicalize script path` — invoke the venv python directly instead.
- Stills: `warden judge-still <png> --palette luap-40 [--symmetry] [--vision]`; anchor readiness: `warden judge-still <png> --start-image [--target-height 40 | --size-tier 48-64] [--margin 3] [--facing south] [--char-id ID]`; against an approved anchor: `warden judge-still <view.png> --reference south.png [--facing north_east]` (needs `OPENROUTER_API_KEY`; offline the `vision_reference` gate FAILS).
- Direction sets: `warden judge-views <dir-or-strip> [--cell 64] [--anchor south.png] [--char-id ID]` (a folder of `<facing>.png` / `<prefix>_<facing>.png` files, or a strip in game order down, down_right, right, up_right, up, up_left, left, down_left).
- Animations: `warden judge-anim <sheet.png> --cell 64 [--walk] [--locomotion legs|wheels|treads]`.
- Gatekeeper: `warden review-check <paths...> --require start_image|views|anim|still` (exit 1 + list of files without a current passed `<image>.gate.json`). All judge commands write that record unless `--no-record`.
- Recipes: `warden recipes` (table), `warden recipes spritefusion direction-set`, `warden recipes rd rotate --json`.
- Others: `warden route "<desc>" --type vehicle`, `warden generate "<desc>" --type icon --provider spritecook --out <dir>`, `warden pad <files|dir> --size 64 [--align bottom-center]`, `warden sheet <files|dir> --out <sheet.png> --palette luap-40 [--engine auto|rust|python]`, `warden pixelize <img> --palette <lospec-slug> [--refine --vision]`, `warden learn seed && warden learn check && warden learn doctor`, `warden learn reflect`, `warden mcp` (`SPRITEWARDEN_NO_LEARN=1` skips the learning scheduler).

## Environment / API keys
- All LLM paths fall back to deterministic local heuristics when unauthenticated, so tests and the QA gates need no keys — EXCEPT the reference comparison (`--reference` / `reference_path`), which reports `unavailable` and fails its gate on purpose.
- `OPENROUTER_API_KEY` — Jev routing, Fusion deliberation, vision judging, OpenRouter image gen. On Windows, `_get_openrouter_key()` (router/jev.py) also reads it from the registry `HKCU\Environment` when the env var is empty. `SPRITEWARDEN_OFFLINE=1` forces `VisionJudge` offline (tests use `VisionJudge(offline=True)` so they never spend).
- `SPRITE_FUSION_API_KEY`, `PIXELLAB_API_KEY` — provider drivers. `ASEPRITE` — path override for Aseprite.exe (else Windows install dirs are auto-discovered).
- `SPRITE_COOK_API_KEY` — SpriteCook driver (alias `SPRITECOOK_API_KEY`; base URL override `SPRITE_COOK_API_URL`/`SPRITECOOK_API_URL`). Read from env, with a Windows `HKCU\Environment` registry fallback like the OpenRouter key.
- `SPRITEWARDEN_PIXEL_SNAPPER` — path override for the Rust `spritefusion-pixel-snapper` binary used by `warden sheet` (else PATH, then `~/.cargo/bin`).
- `SPRITEWARDEN_NO_LEARN=1` — the MCP server does not start the LearningScheduler (no HTTP GETs / LLM budget at startup).

## Architecture
- `src/spritewarden/judge/` — deterministic QA gates: `pixel.py` (pixel_grid; scale inferred: >=640x360 = screenshot multiple, else `detect_block_size` finds 2..16px fake grids, falling back to `sheet/snap.py`'s edge-profile detector), `palette.py` (palette_adherence, `PALETTE_DISPLAY_NAMES`), `bounds.py` (clipping, symmetry), `start_image.py` (`check_start_image`: square canvas, transparent margin, symmetry >=95% for south/north, drawn height vs `SIZE_TIERS`/target/identity cell, stray components via `animation._connected_pieces`, native pixels, palette, identity marker landmarks), `views.py` (`check_direction_set`: ground row +-1, height +-2px, area +-20%, equal component count with extra parts named, tool side per facing from sided identity features (`LEFT_SIDE_SCREEN_SIGN`), palette; `load_direction_frames` / `direction_frame_files`), `animation.py`, `walk.py` (`locomotion` legs|wheels|treads), `loop.py`, `vision.py` (`VisionJudge`: smell test, `compare_to_reference` -> `ReferenceComparison` -> `reference_gate`, `OrchestratedVerdict` hard-fails on anomalies / perspective mismatch when the model looked). Entry fns: `evaluate_still(start_image=, identity=)`, `evaluate_animation(locomotion=)`.
- `src/spritewarden/gates/` — `records.py`: `<image>.gate.json` sidecars (`write_record`, `load_record`, `passed_gates`, `is_gated` re-hashes sha256; `require_passed` = the review gatekeeper). Shape shared with the game repo's `tools/generator_hook.py`: `{"gates": {"<name>": {"passed": ...}}, "sha256", "time", "spritewarden", "params"}`; umbrella names `still`, `start_image`, `views`, `anim`.
- `src/spritewarden/repo/` — `AssetCatalog` (SQLite + FTS5), `CharacterIdentity`/`SceneIdentity` models, palette registry. DB auto-created at `<repo>/data/spritewarden.db`.
- `src/spritewarden/reducer/` — image reducer (`pixelize`: downscale → k-means pre-quantize → dither → vectorized Oklab snap) + `refine` AI tuning loop (contact-sheet vision scoring, critique→param mapping, convergence). Palettes: builtin names, lospec slugs (`na16` / `lospec:<slug>`, cached in `~/.spritewarden/palettes`), JSON/.tres/.hex files.
- `src/spritewarden/learning/` — self-learning KB (`warden learn`): `db.py` (append-only `learning.db`), `models.py`, `taxonomy.py` (canonical perspective/style normalization), `registry.py` (seeded provider doc/tool sources), `acquisition.py` (conditional-GET fetch + snapshot; MCP `tools/list` probe), `mcp_probe.py` (minimal MCP stdio client, also used by `tests/test_mcp_server.py`), `diffing.py` (deterministic diff + significance), `episodes.py` (record attempts), `curation.py` (cluster → strategy + proposal; doc-event → proposal), `summarize.py` (optional capped LLM, deterministic fallback), `proposals.py` (review/apply gate), `scheduler.py` (background watcher), `doctor.py`, `tipshare_bridge.py`, `project_watch.py`, `cli.py`. `PipelineRouter` appends `[learned]` rules from **active** strategies for the matching scope.
- `src/spritewarden/router/` — `PipelineRouter.route_request`: catalog dedup → Jev (`typesafe/jev-1.13`) or OpenRouter Fusion. `recipes.py` + `data/recipes.json` = the per-provider recipe registry (one entry per provider/operation: `start_image` requirements, `prompt_rules`, `forbidden_words`, `arg_limits`, `required_gates_before/after`, `asset_id_params`, `sources`; provider and operation aliases resolve, e.g. `sf`/`direction_set`, `rd`/`rd_advanced_animation__rotate`). `playbook.py` reads it: `sanitize_prompt_for_provider(prompt, provider, operation=None)` strips the registry's patterns (+ dimensions/counts where the provider says so); `determine_fallback_recipe` fills `rules`, `suggested_gates` and `required_gates_before` from the entry. A `GenerationRecipe` carries provider-specific args via `recipe.params`.
- `src/spritewarden/generator/` — `BaseGeneratorDriver` + PixelLab / Sprite Fusion / OpenRouter / **SpriteCook** drivers, plus `registry.py` (`DRIVER_CLASSES`, `get_driver`, `dispatch`) so recipes are executable via `warden generate`. SpriteCook uses sync `/v1/api/generate-sync` + `/v1/api/animate-sync` (async job fallback), enforces the recipe palette via the API `colors` hex list, then re-snaps Oklab locally; asset IDs are canonical for reference/edit/animation.
- `src/spritewarden/sheet/` — `warden sheet`: `snap.py` (Rust `spritefusion-pixel-snapper` wrapper + pure-Python grid-detect/majority-resample + Oklab palette snap fallback; `find_pixel_snapper`, `snap_image`, `detect_pixel_size`) and `builder.py` (`discover_inputs`, `build_sheet`/`build_sheets`: alpha-crop → uniform cell → align → grid compose + JSON manifest). `pad.py` — `pad_files`/`pad_image`: place provider output (varying canvas sizes, edge-hugging art) on a uniform aligned canvas (`--size`/`--canvas WxH`, per-frame `--grow N`, align/margin, `--fit clip|shrink`, optional palette snap, `--in-place`). MCP tools: `build_sprite_sheet`, `pad_sprite`.
- `src/spritewarden/server/` — MCP server (`warden mcp`). Startup is lazy: `AssetCatalog`/`PipelineRouter` are built on first use (`get_catalog()`, `get_router()`), heavy modules import inside the tools, the learning scheduler is optional. Tools: `search_art`, `get_character_identity`, `register_character_identity`, `route_generation`, `get_recipe`, `judge_still` (start_image, reference_path, write_gate_record), `judge_direction_set`, `judge_animation` (locomotion), `review_check`, `build_sprite_sheet`, `pad_sprite`, `open_in_aseprite`, `pixelize_image`, `learn_status`, `list_learned_proposals`, `approve_learned_proposal`, `record_learning_episode`. Resources: `spritewarden://recipes|playbook|proposals|providers|learn-status`. `src/spritewarden/tools/` — Aseprite integration (Windows-only).
- `scripts/ingest_game_assets.py` — one-off seeder for the `i-require-maintenance` game.

## Gotchas
- Repo was renamed from `slaygent`. Stale `__pycache__` can make tracebacks show `slaygent\...` paths; the `.venv` editable install (`_editable_impl_sprite_warden.pth`) points at this repo's `src`.
- `test_find_aseprite` requires Aseprite to be installed on this host. All other tests run offline; `tests/test_mcp_server.py` spawns `python -m spritewarden.cli mcp` with `SPRITEWARDEN_NO_LEARN=1`.
- Built-in palettes are hardcoded in `judge/palette.py`; `luap-40` is the default reference palette (also `luap-40-plus`, `sweetie-16`). `write_gpl_palette` writes the display name (`Luap-40`) on the `Name:` line and lowercase ids in swatch names.
- `load_palette` treats any bare lowercase slug string (no path separators/extension, not a builtin) as a lospec palette-list slug and fetches it; unknown slugs raise FileNotFoundError only after the fetch fails. Override the cache with `SPRITEWARDEN_PALETTE_CACHE`.
- `pixel_grid` scale inference: `detect_block_size` only counts fully opaque blocks and demands that the half-step offset breaks them, so a flat silhouette is not a grid; a bilinear (blurred) upscale under 640x360 is still invisible to it (reported as native). `scale_source` in the gate metrics says which path decided (`given`, `screenshot`, `detected`, `estimated`, `native`).
- `check_start_image` symmetry runs only for south/north facings (`SYMMETRIC_FACINGS`); `size_tier` must be one of `SIZE_TIERS` (`16-32`, `48-64`, `96`, `128`), or pass `target_height` (+-10%). Strays are 8-connected components under 6% of the main mass; larger detached parts are warnings.
- `check_direction_set` tool-side check needs identity features whose name/description says `left` or `right` AND a `marker_hex`; E/W are skipped (sides overlap in x). Frames must share one canvas size.
- Gate records are written even when gates fail (verdicts are per gate); `passed_gates`/`is_gated` return nothing when the image's sha256 changed. `review-check --require` accepts several names (comma-separated), any one satisfies.
- `walk_mechanics` with `locomotion=wheels|treads` treats the lowest contact row as ground (range must be <=1px); a band that never changes only warns ("does not visibly turn").
- The recipe registry is JSON (no pyyaml); `router/recipes.registry()` is lru-cached; `load_registry(path)` loads another file. Operation names kept for compatibility: fallback recipes still use `animate_character_v3` (alias of `animate_skeleton`) and spritecook `generate` (alias of `generate_game_art`).
- Learning DB lives at `<repo>/data/learning.db`; override with `SPRITEWARDEN_LEARNING_DB`. Background-check cadence/caps: `SPRITEWARDEN_LEARN_INTERVAL`, `SPRITEWARDEN_LEARN_MONTHLY_USD`. The first check of a source only establishes a **baseline snapshot** (no event); `doc_events` fire only on real transitions.
- MCP `tools/list` drift probing needs a probe command per provider, e.g. `SPRITEWARDEN_MCP_PROBES='{"pixellab":["python","-m","pixellab_mcp"]}'`; without it `mcp_tools` sources are skipped silently.
- Lospec has no stable machine-readable index (its palette-list HTML is per-request dynamic), so it is **not** a watched source; palettes are fetched directly via `load_palette`/`pixelize --palette`.
- `warden sheet` resolves the Rust snapper via `SPRITEWARDEN_PIXEL_SNAPPER` → PATH → `~/.cargo/bin` (install: `cargo install spritefusion-pixel-snapper`). Rust palette recolor is straight RGB, so the builder re-snaps with Oklab afterwards; when the binary is missing/errors it silently uses the Python grid-detect + majority-resample fallback.
